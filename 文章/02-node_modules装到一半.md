# 装到一半的 node_modules：Windows 上最阴的安装失败

## 现象

`pnpm install` 或 `npm install` 打印了一堆进度，最后没有明显的红色报错。你重启软件，它说：

```
Cannot find module 'xxx'
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'xxx' imported from ...
```

你去 `node_modules` 里看那个包，目录**是存在的**。再往里看：

```
node_modules/dsh-openwrite/
  presets/
  release/
  scripts/
  vendor/
```

`package.json` 没了，`plugin.mjs` 没了，`packages/` 没了。

目录在，但只有后半截。

---

## 为什么

Windows 的文件锁和 Unix 不是一回事。

Unix 上你删掉一个正在被打开的文件，进程继续用它的 inode，删除只是把目录项摘掉——所以包管理器可以放心地覆盖。

Windows 上文件被进程打开着，`Delete` 或 `Rename` 直接返回 `EPERM`（Access denied）。包管理器的安装流程是「先删旧目录，再写新目录」：

1. 删旧目录 → 删到一半，碰到被锁的文件 → `EPERM`
2. 包管理器**不会回滚已经删掉的部分**
3. 写新目录时，有些文件已经存在（刚才没删掉的），跳过
4. 最终结果：新旧混合的残骸

而且这个错误经常被吞掉。`pnpm importPackage` 这种内部调用失败，上层可能只打一行警告就继续了。

**谁锁的？** 就是你要装插件的那个软件自己。它把 `node_modules` 里的代码加载进内存了，文件句柄没释放。

---

## 怎么判断是不是这个问题

三步，三十秒：

```powershell
# 1. 目录里应该有 package.json，没有就是残骸
Test-Path node_modules\<包名>\package.json

# 2. 对比 lockfile 里声明的版本
Select-String -Path pnpm-lock.yaml -Pattern '<包名>'

# 3. 数一下文件数量，跟备份比
(Get-ChildItem node_modules\<包名> -Recurse -File).Count
```

如果 1 是 `False`，不用再查了，就是这个坑。

---

## 怎么修

### 第一步：找到并杀掉锁文件的进程

别按名字猜，按命令行匹配：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*<包名>*' } |
  Select-Object ProcessId, Name, @{n='cmd';e={$_.CommandLine.Substring(0,[Math]::Min(100,$_.CommandLine.Length))}}
```

确认之后 `Stop-Process -Id <pid> -Force`。

如果软件是 GUI 的，最稳的办法是**整个退出**，不是关窗口——很多 Electron 应用关窗口不退出主进程。

### 第二步：从备份恢复，不要直接重装

重装有概率再撞一次。如果有 `.ignored`、`.backup`、`node_modules.bak-*` 这类目录，先 robocopy 回来：

```powershell
robocopy "node_modules\.ignored\dsh-openwrite.bak-0.2.23-20261024" `
         "node_modules\dsh-openwrite" /E /NFL /NDL
```

**恢复前对齐三方版本**，否则会引入更难查的问题：

- venv / 运行时里装的版本
- profile 的 `package.json` 里声明的版本
- `lockfile` 里锁定的版本

这三个不一致的时候，先统一再装。我这次是 `0.2.23 / 0.2.23 / 0.2.23`，而当时有个 `0.2.25` 的死 lease 在捣乱，清掉才干净。

### 第三步：验证，别信退出码

```powershell
# 逐个验证子路径能不能解析
node -e "console.log(require.resolve('<包名>/tools'))"
node -e "console.log(require.resolve('<包名>/plugin.mjs'))"
```

全部打印出路径才算好。

---

## 怎么预防

**1. 装之前退出软件。** 这条能解决 90% 的情况。

**2. 装之前备份。**

```powershell
Copy-Item node_modules\<包名> "node_modules\<包名>.bak-$(Get-Date -Format yyyyMMddHHmmss)" -Recurse
```

**3. 看退出码。** `pnpm install; echo $LASTEXITCODE`。0 才是真的成功。

**4. 装完立刻验证 resolve，而不是启动软件看界面。** 界面可能因为别的原因不显示，会误导你。

---

## 一个更隐蔽的变种

如果你看到的是：

```
Error: EPERM: operation not permitted, rename '...\node_modules\.pnpm\xxx' -> '...'
```

这是 `pnpm` 的 store 在跨盘符硬链接失败。`pnpm` 默认把包存在同一个盘，如果 store 在 C 盘而项目在 D 盘，会退化成复制，然后撞上同样的锁问题。

修法：

```powershell
pnpm config set store-dir D:\pnpm-store
# 或者强制复制模式
$env:UV_LINK_MODE="copy"
```

---

## 一句话

**`node_modules` 目录存在 ≠ 包装好了。** 检查 `package.json` 在不在，检查 `require.resolve` 通不通，别的都是猜。
